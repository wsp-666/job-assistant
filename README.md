# 求职助手 2.0

本地优先的个人求职工作台：采集并管理 BOSS 与招聘官网岗位，结合简历完成匹配、沟通内容与定向改写，使用多维表/看板/日历管理投递进度，并通过 Edge 扩展提供 BOSS 沟通和实验性网申辅助。最终内容核对与投递提交由用户完成。

## 核心能力

- 岗位采集与信息库：支持 BOSS 插件采集、企业招聘源抓取、搜索筛选与匹配评分；内置 15,942 条有效岗位，采用数据库检索和 5 条分页，支持公司/岗位/城市搜索、岗位分类、推荐视图及外链跳转。
- 推进池：维护 860 条核心推荐与可投递岗位，可从岗位库加入并继续转为实际投递记录。
- 投递工作台：P0–P4 优先级、14 个投递阶段、表格/看板/日历、联系人、跟进时间、面试时间、标签、备注和变更时间线。
- 进度导入：一键导入飞书导出的 `.xlsx`、CSV/TSV 或 JSON；自动识别中英文列名，按岗位链接或“公司 + 岗位”去重合并，空白字段不覆盖原记录。
- 分岗资料：内置 15 个岗位方向的实习经历、项目经历、自我评价及精简版文案，并绑定对应简历，便于选择、复制和维护。
- 简历管理：内置 14 份方向简历，可按目标岗位切换；HTML 版本可直接在浏览器中打印导出。
- AI 辅助：提供职责/待遇/公司三维匹配、解释理由、沟通话术和简历定向改写，使用结构化输出、超时和本地模板兜底。
- BOSS 沟通：读取 JD、评分、生成定制话术、填入沟通框；可选择提交前确认。
- 投递队列：支持选中岗位或按优先级与最低匹配分创建队列，任务写入 SQLite，可暂停、恢复、取消并在刷新后继续。
- 实验性网申辅助：已实现统一资料、语义字段识别、附件上传、动态经历添加、日期组件适配、登录/验证码暂停和最终提交保护；因招聘网站自定义组件差异较大，当前默认隐藏并作为实验模块保留，不宣称全站稳定兼容。
- 本地数据：岗位、简历、投递和资料默认保存在本机 SQLite；账号/会员数据与业务数据分离。
- 会员与运营：可选云端账户/会员服务；个人收款码订单支持恢复、过期、取消、付款申报、管理员核验和驳回，商户支付在官方签名与回调完成前明确禁用。

## 架构

```text
用户电脑
├─ FastAPI 本地服务 :8000
│  ├─ SQLite：简历、岗位、投递事件、队列与设置
│  └─ React 管理台静态文件
├─ Edge MV3 扩展
│  ├─ BOSS JD 采集、匹配、话术生成与沟通辅助
│  └─ 实验性通用表单识别、经历动态添加、附件上传与队列执行器
└─ 可选云会员服务
   └─ MySQL：用户、会员、支付订单（不保存岗位与简历）
```

详细模块、状态机与数据流见 [架构文档](docs/ARCHITECTURE.md)。

## 快速开始

### 普通使用

1. 双击 `启动求职助手.bat`，打开 <http://127.0.0.1:8000>。
2. 在“岗位信息库”搜索公司、岗位或城市；需要推进的岗位加入推进池或投递工作台。
3. 在“简历管理”和“投递资料”选择对应岗位方向，核对实习、项目和问答文案。
4. Edge 打开 `edge://extensions`，开启开发人员模式，加载 `apps/extension/dist`。
5. 进入“投递工作台”，可一键导入已有求职进度，并在表格、看板或日历中维护笔试、测评、一面、二面和 Offer 等阶段。
6. 点击岗位链接进入招聘官网，人工完成登录、验证码、表单核对和最终提交；BOSS 场景可使用插件辅助读取 JD 与生成沟通话术，实验性通用填写能力默认隐藏。

### 源码开发

```powershell
./scripts/install.ps1
./scripts/start.ps1
```

Web 开发服务器与扩展：

```powershell
cd apps/web
npm run dev

cd ../extension
npm run dev
```

本机默认使用 SQLite，无需 MySQL。AI Key 在 `.env` 中配置；密钥文件、数据库、简历、构建产物和依赖目录均已排除在 Git 之外。

## 使用边界

- 不读取、不保存招聘网站密码；登录状态由各网站和 Edge 自己维护。
- 验证码、短信、扫码和滑块必须由用户完成。
- 通用表单引擎与投递队列已完成原型和多轮组件适配，但招聘官网包含大量自定义日期、级联选择、动态经历和附件规则，当前默认隐藏为实验能力，不宣称全站兼容。
- 原生字段覆盖率较高，自定义组件可能停在人工接管；分岗资料和 AI 输出均需核对事实、日期、附件及必填项。
- 默认不点击最终提交。即使显式开启高风险模式，未识别到明确提交按钮、必填项未完成或结果无法确认时也会暂停。
- 高频批量投递可能触发第三方平台限制，使用者应遵守对应网站规则并控制投递数量。

## 支付模式

- `PAYMENT_MODE=personal_qr`：个人收款码 + 人工核验，正式默认；需先上传对应渠道收款码。
- `PAYMENT_MODE=mock` 且 `PAYMENT_MOCK=true`：只用于本地开发测试。
- `PAYMENT_MODE=merchant`：代码会明确拒绝创建订单，直到接入官方下单、签名校验与异步回调；不会生成伪支付链接。

云端必须配置至少 32 位随机 `JWT_SECRET` 和至少 16 位 `LICENSE_ADMIN_SECRET`，否则服务拒绝启动。
